## LinkUp 0.3.0 / Android code 9 — security and private-network candidate

This update addresses the reviewed fixed-epoch, stranger-mailbox, screenshot and call/update parsing gaps. New pairwise sessions perform standard MLS UpdatePath commits with durable delivery and encrypted acknowledgments. Both phones and the mailbox server must be updated. Older sessions keep their history but require **Reconnect encryption** before new messages/calls. The relay's v1 snapshot migration drops old pending ciphertext; do not promise that undelivered old mail survives upgrading the server.

The relay now requires a signed recipient permission list for key-package claims and delivery. Removing a friend cancels local unsent work, retires the live session, preserves read-only history and revokes relay access when the server can be reached. Already-sent messages can still arrive. Accepted-friend relationships are visible to the relay as authorization metadata. Global abuse controls remain an operator responsibility.

Android's **You → Connection → Private network** now supports explicit WireGuard enrollment, consent and per-friend routes. Independent native tunnel keys are encrypted with Android Keystore. Messaging uses signed offers, pinned TLS and MLS inside the tunnel. Private mode disables the mailbox and calls, remains foreground-only, and stops on lock/revocation/expiry without switching delivery routes. Only Android 9+ supports this integration; web does not operate the tunnel. The hub can see traffic metadata but cannot decrypt the MLS payloads.

The user chose self-hosting and has no server yet. [Server preparation and two-phone checks](deploy/vpn/README.md) are provided; no server, VPN subscription or public endpoint was purchased or deployed. WireGuard's JNI engine is rebuilt from pinned source using a maintained Go runtime. OpenSSL 3.6.5 is also rebuilt from pinned upstream source, replacing QuickCrypto’s 3.6.2. Android primitive-vector tests passed and the rebuilt WireGuard library loaded on the emulator. The signed local 0.3.0 test APK and corresponding source archive are available. This is not a public GitHub release.

Verification so far: **237/237 app tests**, **35/35 relay tests**, and **3/3 server-policy tests** passed. The final app run includes real 64-message renewal, call renewal deadlines, replay/crash/expiry cases, account-bound VPN enrollment, transport separation, friend removal and the bounded public-signature cache. Lint, typecheck and web export passed. The earlier full run was deliberately stopped after the cache change and superseded by this complete run. Final Android assembly and all **22 native JVM tests** passed, including VPN route validation and unchanged-enrollment socket leases. Three separate permanent CNG dependency-substitution regressions also passed. The APK passed exact bundled-source checks, same-certificate V2/V3 signing, VPN manifest/permission verification, rebuilt WireGuard binary comparison, native notice equality, and patched OpenSSL 3.6.5 inclusion with 3.6.2 absent from QuickCrypto. Gradle’s linked static crypto libraries match the verified AAR.

APK SHA-256: `1e1dc89d8ddd5c4f57e4543ca7b1420ab27036d92eddb81a61c2b029a0384801`. Update installation over the existing app succeeded on the Android 36 arm64 emulator, preserving installation data; package metadata confirms version 0.3.0/code 9. No real account, application UI or private network was opened for this check. Build and native-library provenance are saved alongside the artifact. Source-built dependencies and deterministic AAR packaging are verified locally; independent cross-host reproducibility is not claimed.

Required before production: actual phone/hub/blocked-UDP/network-change/expiry testing; independent cryptographic and application assessment; resolution or independent assessment of remaining tooling advisories and the rest of the native dependency chain. `ts-mls` remains unaudited. Two historical receive epochs intentionally bound delayed-message recovery. A saved vault backup can retain history and earlier secrets; JavaScript/managed-string erasure and hardware anti-rollback are not guaranteed.
